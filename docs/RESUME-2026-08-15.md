## Where the jitter investigation actually stands

**Read this before proposing anything.** Several confident conclusions from 13 August were
wrong, and the corrections matter more than the theories.

### The headline number was an artifact

`capture-gap-probe.py` summed only the SHORTFALLS and called the total "audio never
captured":

```python
deficit_ms = max(0.0, (expected - frames)) / nominal * 1000.0
```

On a symmetric noisy measurement that returns a large number even with **zero** real loss.
Simulated with no loss at all and the observed spread of 1411ppm, that method reports
0.43 ms/s. It was reporting 0.710 and I called it lost audio for an entire evening.

Corrected, on the same live stream:

```
NET RATE ERROR  -96 ppm +/- 183 (standard error)  ->  within noise of zero
```

**Nothing is being lost at the capture.** Which retracts everything built on that number,
including "req_number 8->32 made no difference" — that was noise compared against noise.

### What has been genuinely excluded, with evidence

| Theory | Verdict |
|---|---|
| Network lateness | 0% loss over 60 pings; buffer 250→400→600 changed nothing |
| Clock drift / rate mismatch | ring never fills past one period (`avail_max` 960) |
| dwc2 SOF interrupt storm | **5,041/s** measured; that fault produces 250,000+ |
| `req_number` too shallow | 8→32 changed nothing — though the measurement was noise |
| Under-voltage | 0.00% over 500s, now readable |
| Capture loss | net rate error within noise of zero |

The fault is **intermittent and was not present** during the last measurements. That is why
the next step is comparison, not another hypothesis.

### The instrument that replaces guessing

Four healthy references are banked in `~/Downloads/netbridge-snapshots/`:

```
              good   good2  good3  good-deep
rate error   +508    -93     +2     -70   ppm
path spread   3.7    2.6    6.1    12.9   ms
ring max      912    912    960     864
```

**That spread is the finding.** These wander this much while the audio sounds fine, so
anything inside those bands is normal.

When the jitter returns:

```bash
python3 tools/nb-snapshot.py --label bad --deep
python3 tools/nb-snapshot.py --compare good-deep bad
```

It prints every metric from all three devices side by side and marks what changed. The row
that moves names the device; the rows that do not move eliminate theirs.

## Habits worth keeping from 13–14 August

- Take a healthy reference BEFORE diagnosing. Every wrong turn came from judging a reading
  on whether it looked wrong, with nothing to compare it to.
- Never change the gadget on a running bridge. Two outages, both needing a physical power
  cycle, both from writes that could have been reads.
- A one-sided metric on a noisy signal is not a measurement.
- Run the test twice: convergence is not syntax.
